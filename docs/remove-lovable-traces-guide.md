# Removing Lovable/gpteng Traces: Guide

Status: **Traces found on 2026-09-23 have been removed.** This doc is also the checklist to re-run after pulling changes from Lovable, restoring an old branch, or scaffolding a new file from a template.

nPro started life as a project generated by [Lovable](https://lovable.dev) (marketed under `lovable.dev`, with a companion CDN at `gpteng.co`
and an npm package `lovable-tagger`). Lovable-generated apps carry a few fingerprints that have nothing to do with the app itself: a live-editing
script tag, a dev-only babel/SWC tagging plugin, and sometimes template metadata (name, homepage, social-preview image) left at their placeholder values.
None of this is secret or dangerous, but it doesn't belong in a personal portfolio someone else might read the source of.

## How to check for traces (run this after any bulk import, branch restore, or template regeneration)

```bash
grep -rniE "lovable|gpteng" --exclude-dir=node_modules --exclude-dir=dist --exclude-dir=.git .
```

Interpreting hits:
- **`index.html` script tag / comment** → delete the `<script src="https://cdn.gpteng.co/...">` line and the "DO NOT REMOVE" comment above it.
- **`vite.config.ts` / `vite.config.js`** → remove the `lovable-tagger` import and its use in the plugins array.
- **`package.json` / `package-lock.json` / `bun.lockb` / `yarn.lock`** → remove the `lovable-tagger` entry from `package.json`, then regenerate whichever lockfile the project uses (`npm install --package-lock-only`, or the yarn/pnpm/bun equivalent). Don't hand-edit a lockfile.
- **`README.md`** → Lovable's default README template includes a "How can I edit this code" section naming Lovable and a `lovable.dev` project URL; replace with real project docs (this repo's README was already clean).
- **Any `og:image`/`twitter:image` still pointing at `lovable.dev`** → point it at the project's own image.
- **`.lovable/` directory or `lovable.config.*`** → not present in this repo, but if one appears (e.g. after re-importing from the Lovable UI), delete it unless you intend to keep syncing with Lovable.

After removing a dependency from `package.json`, always regenerate the lockfile and delete the now-orphaned folder from `node_modules` (or just re-run a clean install) — editing `package.json` alone leaves the package on disk and in the lockfile.

## Things that are template-shaped but NOT Lovable-specific (leave alone unless asked)

- `components.json` (shadcn/ui config) and the `src/components/ui/*` primitives — these come from shadcn/ui, a separate open-source project Lovable happens to scaffold with. Nothing to remove.
- Generic scaffold comments like `// https://vitejs.dev/config/` — these are Vite's own template comment, not Lovable's.
